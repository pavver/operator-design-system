# Releasing

Every release publishes two things:

* A GitHub Release with notes generated from Conventional Commits and the built gallery as a zip file.
* The gallery on GitHub Pages: <https://pavver.github.io/operator-design-system/>.

The gallery is deployed only by releases, so the public page always matches a released version.

## Versioning

The repository follows Semantic Versioning with one version for the whole workspace.
While the version is `0.x`, a minor bump may change component behavior or APIs.

| Change | Bump |
| :--- | :--- |
| New component, new token, new platform | minor |
| Bug fix, documentation | patch |
| Removed or renamed token or API (after `1.0`) | major |

## Steps

1. Make sure `main` contains everything for the release and CI is green.
2. Run the release script from a clean `main`:

   ```bash
   scripts/release.sh 0.2.0 --push
   ```

   It sets the workspace version, runs the same checks as CI, commits `chore(release): v0.2.0`, creates the tag, and pushes both.
3. The [Release workflow](../.github/workflows/release.yml) verifies that the tag matches the workspace version, builds the gallery, publishes the release, and deploys GitHub Pages.

## Release Notes

Notes are generated by [git-cliff](https://git-cliff.org) with [cliff.toml](../cliff.toml).
Only Conventional Commits are included, grouped by type.
Write commit subjects so that they read well in the notes.

## Redeploying the Gallery

Run the Release workflow manually from the Actions tab and choose a tag.
A manual run deploys the gallery without creating a release.
